# 🛗 電梯網頁遊戲 (Elevator Web Game)

本專案是一個專門為喜愛**數字**和**電梯**的幼兒所設計的互動式網頁模擬遊戲。遊戲注重極簡化、視覺驅動與溫和的音效回饋，讓幼兒能自由安全地在網頁上模擬電梯上樓與下樓的完整流程，而不會有任何令人感到驚嚇或不知所措的元素。

幾乎所有檔案都是由 AI 產生，文字敘述難免生硬。

# 👤 使用者指南 (User Section)

本章節介紹如何啟動並遊玩這款電梯遊戲。

## 🎮 遊戲簡介與設計特色
- **無文字負擔**：介面完全不需要閱讀文字，全憑直覺的數字與圖示引導，非常適合年幼的孩子。
- **溫和無害的反饋**：
  - 音效音量設計柔和，不使用任何尖銳、突兀或驚嚇的聲響。
  - 當輸入無效樓層時，不顯示刺眼的紅色警告，而是以輸入框輕微搖晃與溫和的嗶嗶聲作為視覺和聽覺提示。
- **直覺互動**：按鈕與點擊目標區域大，支援滑鼠 Hover 放大與點擊動畫，提升互動趣味。

## 🕹️ 遊戲玩法與互動方式
1. **輸入目標樓層**：
   - 點擊左側電梯面板的輸入框，輸入你想要去的樓層。
   - **地上樓**：直接輸入數字（例如：`15` 代表 15 樓）。
   - **地下樓**：先輸入字母 `B` 再輸入數字（例如：`B3` 代表地下 3 樓）。
   - 輸入完成後，按下鍵盤上的 **Enter 鍵** 電梯便會關門並出發！
2. **點擊大樓側面剖面圖**：
   - 你也可以直接用滑鼠點擊右側大樓剖面圖上的樓層編號，電梯會自動關門前往該樓層。
3. **觀賞電梯動畫與音效**：
   - 電梯出發前，左右門會平滑關閉。
   - 移動時，面板箭頭會亮起（▲ 代表上行，▼ 代表下行），顯示面板數字會逐層跳動，右側的大樓樓層刻度也會平滑滾動。
   - 當抵達目的地後，會響起清脆的「叮咚」聲，電梯門隨之打開，等待下一次輸入。

## 🚀 本地啟動指南
由於本遊戲使用 Web Audio API，為避免瀏覽器的音效播放安全限制，請透過本地伺服器執行：

- **Windows 系統**：直接雙擊運行目錄下的 [run.bat](file:///d:/elevator_web/run.bat) 即可自動開啟瀏覽器 (`http://localhost:3000`) 遊玩。
- **其他系統**：在專案目錄下執行 `npx serve`（或 `python -m http.server 8080`）後，以瀏覽器開啟指定網址即可。

## 🔊 音效表現說明
遊戲中的所有聲音都模擬了真實電梯的環境音：
- **關門聲**：門開始關閉時，播放柔和的「咻～咔」聲。
- **開門聲**：門開始開啟時，播放柔和的「嘶～」聲。
- **移動環境音**：電梯行駛期間，會持續播放低沉的馬達嗡嗡聲。
- **經過樓層聲**：電梯每經過一層樓，都會發出輕柔的「滴」聲。
- **到達鐘聲**：抵達目的地時，播放清脆悅耳的「叮咚」聲。
- **無效輸入聲**：輸入錯誤時，發出短促溫和的「嗶嗶」聲。

# 💻 開發者指南 (Developer Section)

本章節介紹這款遊戲背後的架構設計、核心技術實作、測試環節以及未來的開發規劃。

## 🛠️ 技術棧與架構設計
- **前端核心**：純 HTML5 (語意化標籤) + Vanilla CSS3 (自訂 Keyframes 動畫) + JavaScript (原生 ES6 Class)。
- **音效合成**：**Web Audio API**（完全不依賴任何外部音效檔案，全部使用振盪器、濾波器與雜訊緩衝器即時程式合成）。
- **測試框架**：Puppeteer (自動化排版與佈局檢查)。

## 🔄 狀態機與流程控制
電梯的運行狀態由狀態機（State Machine）控制，確保狀態流轉的安全與穩定：

```
[*] (頁面載入) ──> 待機中 (IDLE)
                     │
                     │ (輸入有效樓層 + 按 Enter / 點擊剖面圖樓層)
                     ▼
                 關門動畫 (CLOSING) (~1秒，播放關門音效，禁用輸入)
                     │
                     ▼
                 移動中 (MOVING) (逐層跳動，播馬達環境音 + 經過樓層滴聲)
                     │
                     ▼
                 到達目標 (ARRIVING) (停止移動，箭頭熄滅，播放叮咚聲)
                     │
                     ▼
                 開門動畫 (OPENING) (~1秒，播放開門音效)
                     │
                     └─> 回到 待機中 (IDLE) (啟用輸入，聚焦輸入框)
```

## 🎛️ 音效合成引擎規格
所有音效皆在 [audio.js](file:///d:/elevator_web/audio.js) 中透過程式碼即時合成。具備防音訊重疊溢出與使用者首次點擊自動解鎖音訊上下文（AudioContext）的機制：

| 音效類型 | 觸發時機 | 合成原理與參數 | 聽覺風格 |
| :--- | :--- | :--- | :--- |
| **關門聲** | 門開始關閉 | 降頻低通濾波器（3000Hz → 150) 過濾白噪音，結尾處疊加一個低頻正弦波（120Hz → 60Hz）。 | 柔和的「咻～咔」 |
| **開門聲** | 門開始打開 | 升頻低通濾波器（150Hz → 3000Hz）過濾白噪音。 | 柔和的「嘶～」 |
| **移動環境音** | 移動期間持續 | 正弦波振盪器（55Hz）作為基音，並透過低頻振盪器（LFO，8Hz）調變振幅。 | 低沉的馬達嗡嗡聲 |
| **經過樓層聲** | 每經過一層 | 短暫的高頻正弦波脈衝（1200Hz），持續 0.05 秒。 | 輕柔的「滴」 |
| **到達鐘聲** | 抵達目標樓層 | 兩個正弦波振盪器雙音合成（主音 587.33Hz，和音 783.99Hz），搭配指數級衰減（持續 1.5 秒）。 | 清脆的「叮咚」 |
| **錯誤提示音** | 輸入無效 | 兩個短促的方波振盪器脈衝（180Hz），持續 0.08 秒。 | 溫和的「嗶嗶」 |

## ⚙️ 技術實作細節

### 1. 樓層轉換與內部表示法
系統內部統一使用 **整數** 來表示樓層：
- 地下樓表示為負數：`B1` ＝ `-1`，`B3` ＝ `-3` ... 最深到 `B99` ＝ `-99`。
- 地上樓表示為正數：`1` ＝ `1`，`15` ＝ `15` ... 最高到 `999` ＝ `999`。
- **不存在 0 樓**。在計算距離與跳層時，若跨越地下一樓與地上一樓，系統會自動在加減運算中跳過 0：
  ```javascript
  // 範例：從 B1 (-1) 前往 1F (1) 的跨度為 1，而非 2
  ```

### 2. 模擬加減速移動時間算法
當電梯移動跨度大於 10 層時，為模擬真實高層電梯的運作，設計了**加速-巡航-減速**曲線：
- **加速階段**：前 3 層的移動間隔時間逐層減少（2000ms → 1500ms → 1000ms）。
- **減速階段**：最後 3 層的移動間隔時間逐層增加（1000ms → 1500ms → 2000ms）。
- **巡航階段**：中間層高速通過，單層間隔時間根據總移動時間預算自動分配（最高頻率可達每層 50ms）。

### 3. 大樓側面剖面圖滾動與渲染
- 顯示區由 13 個插槽（Slot）組成：中間 11 層為可見區域，上下各 1 個緩衝插槽。
- 移動時，透過 CSS `transform: translateY()` 將整體插槽容器平滑位移。當移動到新樓層時，瞬間更新插槽內容並重置位移量（暫時關閉 CSS Transition），實現無縫滾動。
- 當電梯在高速巡航階段（單層時間 < 80ms）時，會**自動暫停 CSS 滾動動畫**並直接跳轉數字，以確保低階裝置上的效能與畫面流暢度。

### 4. 嚴格的輸入過濾
- 監聽 `keydown` 與 `input` 事件，僅允許輸入 `0-9`、`B`、`b`、`Backspace`、`Delete` 與方向鍵，其餘按鍵直接阻擋。
- `B` 只能出現在首個字元。輸入小寫 `b` 會自動轉換成大寫 `B`。
- 連續按 Enter 鍵會被鎖定（Submit Lock），防止重複提交造成狀態機混亂。

## 🔧 歷史問題修復記錄
1. **GO 按鈕點擊與門無反應問題修復**：
   - **原因**：`style.css` 中 `.door-container` 的 CSS 規則結尾漏掉了一個右大括號 `}`，導致後面說明的 `.door-left.closed` 與 `.door-right.closed` 樣式解析失敗，使門無法合攏。
   - **修復**：補齊 `style.css` 語法大括號，開關門動畫與視覺反饋恢復正常。
2. **Enter 鍵與表單提交一致性修復**：
   - **原因**：原本僅監聽鍵盤 Keydown 的 Enter 事件，在不同作業系統、輸入法或移動端軟鍵盤上容錯率低。
   - **修復**：將輸入框包裹在原生 `<form id="floor-form">` 中，並監聽表單的 `submit` 事件。現在不論是實體鍵盤 Enter、軟鍵盤 Send/Enter，均能統一且流暢地送出樓層。

   - **輸入發送**：自動聚焦輸入框、鍵入目標樓層 `5` 並按下 Enter 鍵。
   - **關門狀態**：驗證門是否開始滑動關閉，並儲存為 `test_closing.png`。
   - **移動狀態**：等待 1.5 秒確認門已關閉且上行箭頭 ▲ 正常發光，並儲存為 `test_moving.png`。
   - **抵達狀態**：等待 9.5 秒，驗證電梯是否準確抵達 5F 且門重新開啟，並儲存為 `test_arrived.png`。
4. **自動終止與清理（重要）**：測試完成後，腳本會自動關閉 Puppeteer 瀏覽器，並**完全關閉/釋放背景啟動的 Web 服務連接埠**，乾淨退出。
